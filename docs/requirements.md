## 2. 서비스 개요

### 2.1 서비스 목적

업무 문서를 업로드하면 AI Agent가 내용을 구조화해 분석하고, 핵심 주장·사실·결정사항을 근거와 함께 요약한다. 사용자가 긴 문서를 읽는 시간과 핵심 정보 탐색 비용을 줄이는 것이 목적이다.

### 2.2 대상 사용자

- 보고서·회의록·계약서·기획서를 검토하는 직장인
- 연구자료의 핵심을 파악하려는 학생·연구자
- 여러 문서의 이슈와 결론을 확인하는 관리자

### 2.3 해결하려는 문제

- 회의록·보고서·계약서처럼 수십 페이지에 이르는 문서를 검토할 때, 사용자는 결론·결정사항·담당자 같은 핵심 정보를 찾기 위해 문서 전체를 읽어야 한다.
- 문서마다 제목 체계와 표현 방식이 달라, 같은 목적의 정보라도 사용자가 직접 검색하고 비교해야 하므로 검토 시간이 길어진다.
- 기존 AI 요약은 각 문장이 원문의 어느 부분에 근거하는지 확인하기 어렵고, 원문에 없는 내용이 섞이면 사용자가 결과를 다시 대조해야 해 신뢰하기 어렵다.

### 2.4 핵심 가치

업로드부터 결과 확인까지의 흐름을 단순화하고, 요약과 근거를 함께 제공해 결과를 빠르게 검토하고 신뢰할 수 있게 한다.

## 3. 요구사항 정의의 전제와 가정

- 1차 MVP는 로그인 없는 단일 사용자 흐름으로 구성한다.
- PDF와 TXT를 우선 지원하며 DOCX·이미지·스캔 문서는 후속 범위로 둔다.
- AI 모델과 API 제공자는 비용, 한국어 성능, 개인정보 처리 조건을 비교해 선정한다.
- 문서는 필요한 기간만 보관하고, 구체적인 기간은 운영 정책에서 확정한다.
- AI 결과는 참고용이며 법률·의료·재무 판단을 대신하지 않는다는 안내를 제공한다.

## 4. 서비스 범위

### 4.1 MVP 포함 범위

문서 업로드, 형식·용량 검증, PDF/TXT 텍스트 추출, AI 분석, 구조화된 요약 결과 표시, 오류 안내, 결과 복사 및 Markdown/TXT 다운로드를 제공한다.

### 4.2 MVP 제외 범위

다중 사용자·권한 관리, 공동 편집, 외부 저장소 연동, OCR, 다중 문서 비교, 모델 학습·개인화, 전문 분야의 자동 판단은 제외한다.

## 5. 사용자 흐름

사용자가 파일을 선택하거나 끌어 놓으면 시스템은 형식과 크기를 검증하고 텍스트를 추출한다. 이후 AI Agent가 문서 유형과 내용을 분석하고, 요약·핵심 내용·키워드·후속 조치를 표시한다. 사용자는 결과를 복사하거나 다운로드한다.

## 6. 기능 요구사항

### FR-01. 문서 업로드

지원 파일을 선택·업로드하고 진행 상태, 파일명, 형식을 표시한다. MVP 권장 제한은 파일당 20MB, 1회 1개다.

### FR-02. 입력 검증

확장자·MIME 타입·용량을 검증하고, 손상 파일·텍스트 추출 불가 파일·실행 파일은 분석 전에 거부한다.

### FR-03. 텍스트 추출

PDF와 TXT에서 분석 가능한 텍스트를 추출하며, 빈 텍스트는 재업로드 또는 다른 형식을 안내한다. 가능한 범위에서 페이지·문단 구조를 보존한다.

### FR-04. AI Agent 분석

추출 원문을 근거로 한 문단 요약, 핵심 내용 3~7개, 키워드, 목적·주제, 결론·주장, 중요 일정·수치·인물·조직, 후속 조치·질문을 생성한다. 근거가 없으면 추측하지 않고 `확인 불가`로 표시하며, 가능한 경우 페이지·문단 위치를 제공한다.

### FR-05. 요약 옵션

요약 길이는 짧음·보통·자세히, 출력 언어는 한국어·원문 언어를 선택한다. 기본값은 한국어·보통이다.

### FR-06. 결과 표시

대기·분석 중·완료·실패 상태를 구분하고, 결과를 요약·핵심 내용·상세 분석으로 나누어 표시한다. 이전 결과나 원문 없는 결과가 노출되지 않도록 한다.

### FR-07. 결과 활용

전체 또는 항목별 결과를 복사하고 Markdown/TXT로 다운로드할 수 있어야 한다. 다운로드 파일에는 생성 시각과 옵션을 포함할 수 있다.

### FR-08. 오류 및 예외 처리

AI API·네트워크 오류와 시간 초과 시 원인과 재시도 방법을 안내한다. API 키, 내부 경로, 스택 트레이스는 사용자에게 노출하지 않는다.

### FR-09. 삭제 및 초기화

현재 문서와 결과를 초기화하고 업로드 초기 상태로 돌아갈 수 있어야 한다. 서버 저장 시 보관 정책과 초기화 요청에 따라 원문·결과를 삭제한다.

## 7. 비기능 요구사항

### NFR-01. 사용성

별도 교육 없이 사용할 수 있어야 하며, 분석 상태를 명확히 표시한다. 데스크톱을 우선 지원하되 태블릿·모바일에도 반응형으로 제공한다.

### NFR-02. 성능

일반적인 20MB 이하 텍스트 문서는 60초 이내 결과 제공을 목표로 한다. 처리 중 화면이 멈추지 않으며, 긴 문서에는 제한과 예상 대기 시간을 안내한다.

### NFR-03. 신뢰성

실패 시 원문을 안전하게 보존하고, 빈 응답·형식 오류 결과는 노출하지 않는다. 중복 요청과 불필요한 API 비용을 방지한다.

### NFR-04. 보안 및 개인정보

비밀 값은 환경 변수 또는 안전한 저장소로 관리한다. 허용 경로만 처리하고 출력값은 이스케이프하며, 원문·API 키를 로그에 남기지 않는다. 외부 API 전송·보관 정책을 안내한다.

### NFR-05. 유지보수성

파일 처리, 텍스트 추출, AI 분석, 결과 변환을 분리한다. 모델·프롬프트 변경의 영향을 최소화하고 민감정보 없는 오류·처리시간 로그를 남긴다.

### NFR-06. 접근성

키보드만으로 주요 기능을 사용할 수 있어야 한다. 컨트롤에 명확한 이름을 부여하고, 상태는 색상 외 텍스트나 아이콘으로도 전달한다.

## 8. 데이터 요구사항

### 8.1 입력 데이터

파일명, 형식, 크기, 원문 또는 추출 텍스트, 요약 길이, 출력 언어를 다룬다.

### 8.2 출력 데이터

처리 상태, 문서 유형·주제, 요약, 핵심 내용, 키워드, 결론·주장, 중요 사실·수치, 후속 조치·질문, 근거 위치, 오류 코드·안내 문구를 제공한다.

## 9. AI Agent 동작 기준

AI Agent는 원문 근거를 우선하고 불확실성을 표시하며 과도한 추론을 하지 않는다. 원문에 없는 사실·출처·수치는 생성하지 않고, 필수 항목 누락·비정상적으로 짧은 응답·구조화 형식 오류를 애플리케이션에서 검증한다. 결과에는 전문 자문이나 최종 결정을 대체하지 않는다는 안전 고지를 포함한다.

## 10. 주요 사용 사례

### UC-01. 보고서 요약

보고서의 목적, 핵심 내용, 결론, 후속 조치를 요약한다.

### UC-02. 회의록에서 할 일 찾기

결정사항, 담당자, 일정, 미해결 질문을 구분해 표시하며, 원문에 없는 정보는 비워 두거나 확인 불가로 표시한다.

### UC-03. 분석 실패 재시도

추출·분석 실패 원인을 안내하고 같은 문서 재시도 또는 다른 문서 선택을 지원한다.

## 11. MVP 수용 기준

- PDF/TXT 정상 문서를 업로드하고 텍스트 추출·분석할 수 있다.
- 미지원 형식과 용량 초과 파일이 이유와 함께 거부된다.
- 결과에 요약, 핵심 내용, 키워드, 결론·주장, 후속 조치가 표시된다.
- 근거 없는 정보는 사실처럼 표시되지 않고 확인 불가로 처리된다.
- 분석 중·완료·실패 상태가 구분되며 결과를 복사·다운로드할 수 있다.
- API 키와 원문이 소스 코드·일반 로그에 노출되지 않는다.

## 12. 테스트 요구사항

### 정상 시나리오

한국어 TXT, 여러 페이지의 텍스트 기반 PDF, 요약 길이·언어 변경, 결과 복사·다운로드를 검증한다.

### 예외 시나리오

빈 파일, 손상 PDF, 미지원 확장자, 용량 초과, 이미지 PDF, API 키 누락·API 오류, 네트워크 단절·시간 초과, 핵심 정보가 없는 문서를 검증한다. 각 테스트는 입력·기대 결과·실제 결과·통과 여부를 기록한다.

## 13. 운영 및 관리 요구사항

AI API 사용량, 오류율, 모델명, 프롬프트 버전, 처리 시간을 민감정보 없이 관리한다. 문서 보관 기간과 삭제 정책은 공개 전에 확정한다.

## 14. 향후 개선 방향

DOCX·HWP·이미지·OCR, 다중 문서 비교·통합 요약, 계정·이력 관리, 문서 유형별 템플릿, 페이지 기반 근거, 품질 평가·사용자 피드백, 조직 권한·감사 로그를 검토한다.

## 15. 미결정 사항

최종 AI 모델·API 제공자, 최대 파일 크기·문서 길이, 저장·보관 정책, 인증 도입 시점, 근거 위치 단위, 운영·배포 환경과 예상 동시 사용자를 구현 전에 결정한다.
