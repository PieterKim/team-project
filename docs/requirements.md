## 2. 서비스 개요

### 2.1 서비스 목적

사용자가 업무 문서를 업로드하면 AI Agent가 문서의 내용을 구조화하여 분석하고, 핵심 내용을 짧고 이해하기 쉬운 요약으로 제공한다. 긴 문서를 직접 읽는 데 필요한 시간을 줄이고, 핵심 주장·주요 사실·결정사항을 빠르게 파악할 수 있도록 하는 것이 목적이다.

### 2.2 대상 사용자

- 회의록, 보고서, 계약서, 기획서 등을 빠르게 검토해야 하는 직장인
- 연구자료와 참고문헌의 핵심 내용을 파악하려는 학생·연구자
- 여러 문서에서 주요 이슈와 결론을 비교해야 하는 관리자 또는 사용자

### 2.3 해결하려는 문제

- 긴 문서를 처음부터 끝까지 읽는 데 시간이 많이 걸린다.
- 문서마다 핵심 정보와 구조가 달라 필요한 내용을 찾기 어렵다.
- AI가 생성한 요약의 근거를 확인하기 어렵거나 원문에 없는 내용이 섞일 수 있다.

### 2.4 핵심 가치

문서 업로드부터 분석 결과 확인까지의 과정을 단순화하고, 요약과 함께 핵심 근거를 제시하여 사용자가 결과를 신뢰하고 재검토할 수 있게 한다.

## 3. 요구사항 정의의 전제와 가정

- 1차 MVP는 로그인 없이 단일 사용자가 문서를 업로드하고 결과를 확인하는 흐름을 대상으로 한다.
- MVP의 입력 형식은 PDF와 TXT를 우선 지원한다. DOCX·이미지·스캔 문서는 후속 범위로 둔다.
- AI 모델과 API 제공자는 구현 단계에서 비용, 한국어 성능, 개인정보 처리 조건을 비교하여 선정한다.
- 업로드 문서는 서비스 운영 목적에 필요한 기간 동안만 저장하며, 구체적인 보관 기간은 운영 정책 확정 시 결정한다.
- AI 결과는 참고용이며 법률·의료·재무 판단을 대신하지 않는다는 안내를 제공한다.

## 4. 서비스 범위

### 4.1 MVP 포함 범위

1. 문서 파일 업로드
2. 파일 형식·용량 검증
3. 문서 텍스트 추출
4. AI Agent를 통한 문서 분석
5. 핵심 요약과 구조화된 분석 결과 제공
6. 분석 실패·지원하지 않는 문서에 대한 오류 안내
7. 결과 복사 및 다운로드

### 4.2 MVP 제외 범위

- 다중 사용자 계정, 조직·권한 관리
- 실시간 공동 편집 및 댓글
- 외부 저장소 연동
- 스캔 문서의 OCR
- 여러 문서 간 비교 분석
- 모델 학습 및 사용자별 맞춤형 파인튜닝
- 법률·의료·재무 분야의 전문 판단 또는 자동 의사결정

## 5. 사용자 흐름

1. 사용자가 서비스에 접속한다.
2. 사용자가 분석할 파일을 선택하거나 업로드 영역에 끌어 놓는다.
3. 시스템이 확장자와 파일 크기를 검증한다.
4. 시스템이 문서에서 텍스트를 추출한다.
5. AI Agent가 문서 유형과 내용을 분석한다.
6. 시스템이 요약, 핵심 내용, 주요 키워드, 후속 조치 등을 화면에 표시한다.
7. 사용자가 결과를 복사하거나 파일로 다운로드한다.

## 6. 기능 요구사항

### FR-01. 문서 업로드

- 사용자는 지원되는 문서 파일을 선택하여 업로드할 수 있어야 한다.
- 업로드 중에는 진행 상태를 표시해야 한다.
- 파일명과 파일 형식을 사용자에게 표시해야 한다.
- MVP 권장 제한: 파일당 최대 20MB, 한 번에 1개 파일. 실제 제한은 구현 전에 확정한다.

### FR-02. 입력 검증

- 시스템은 허용 확장자와 MIME 타입을 검증해야 한다.
- 제한 용량을 초과한 파일은 분석하지 않고 원인을 안내해야 한다.
- 손상되었거나 텍스트를 추출할 수 없는 파일은 실패 상태로 처리해야 한다.
- 실행 파일 등 문서가 아닌 파일은 업로드 단계에서 거부해야 한다.

### FR-03. 텍스트 추출

- 시스템은 PDF 및 TXT 파일에서 분석 가능한 텍스트를 추출해야 한다.
- 추출된 텍스트가 비어 있거나 지나치게 짧으면 사용자에게 재업로드 또는 다른 형식 사용을 안내해야 한다.
- 페이지 구분 또는 문단 구조 등 분석에 필요한 기본 문서 구조를 가능한 범위에서 보존해야 한다.

### FR-04. AI Agent 분석

- AI Agent는 추출된 원문만을 주요 근거로 사용하여 분석해야 한다.
- 분석 결과에는 다음 항목을 포함해야 한다.
  - 한 문단 요약
  - 핵심 내용 3~7개
  - 주요 키워드
  - 문서의 목적 또는 주제
  - 결론·결정사항 또는 주요 주장
  - 언급된 일정, 수치, 인물, 조직 등 중요 정보
  - 문서에서 확인되는 후속 조치 또는 질문
- 원문에서 확인되지 않는 내용은 추측하지 않고, 확인 불가로 표시해야 한다.
- 분석 결과에 원문 근거의 페이지 또는 문단 위치를 가능한 경우 함께 표시해야 한다.

### FR-05. 요약 옵션

- 사용자는 요약 길이를 짧음·보통·자세히 중에서 선택할 수 있어야 한다.
- 사용자는 분석 결과의 출력 언어를 한국어 또는 원문 언어로 선택할 수 있어야 한다.
- 옵션을 선택하지 않은 경우 한국어·보통 길이를 기본값으로 사용한다.

### FR-06. 결과 표시

- 시스템은 분석 상태를 대기·분석 중·완료·실패로 구분하여 표시해야 한다.
- 결과는 요약, 핵심 내용, 상세 분석 영역으로 나누어 읽기 쉽게 제공해야 한다.
- 원문이 없는 상태에서 결과를 표시하거나, 이전 사용자의 결과가 노출되어서는 안 된다.
- 긴 결과는 화면에서 스크롤할 수 있어야 한다.

### FR-07. 결과 활용

- 사용자는 요약 결과 전체 또는 항목별 내용을 클립보드에 복사할 수 있어야 한다.
- 사용자는 결과를 Markdown 또는 TXT 형식으로 다운로드할 수 있어야 한다.
- 다운로드 파일에는 생성일시와 사용한 요약 옵션을 포함할 수 있다.

### FR-08. 오류 및 예외 처리

- AI API 오류, 네트워크 오류, 처리 시간 초과가 발생하면 재시도 가능한 안내를 제공해야 한다.
- 오류 메시지는 사용자가 이해할 수 있는 원인과 다음 행동을 포함해야 한다.
- API 키, 내부 경로, 스택 트레이스 등 민감하거나 불필요한 내부 정보는 사용자 화면에 노출하지 않아야 한다.

### FR-09. 삭제 및 초기화

- 사용자는 현재 업로드 문서와 분석 결과를 초기화할 수 있어야 한다.
- 초기화 후 화면에는 새 문서를 업로드할 수 있는 초기 상태가 표시되어야 한다.
- 서버에 파일을 저장하는 경우, 사용자 초기화 요청과 보관 정책에 따라 원문 및 결과를 삭제해야 한다.

## 7. 비기능 요구사항

### NFR-01. 사용성

- 처음 사용하는 사람도 별도 교육 없이 업로드부터 결과 확인까지 진행할 수 있어야 한다.
- 분석 중에는 진행 상태와 현재 작업을 명확히 표시해야 한다.
- 데스크톱 화면을 우선 지원하고, 주요 기능은 태블릿·모바일에서도 사용할 수 있도록 반응형으로 구성한다.

### NFR-02. 성능

- 일반적인 20MB 이하 텍스트 문서는 목표 60초 이내에 결과를 제공한다.
- 업로드와 분석 요청 중 화면이 멈추지 않아야 한다.
- 대용량 또는 긴 문서는 처리 제한과 예상 대기 안내를 제공한다.

### NFR-03. 신뢰성

- 분석 실패 시 원문 파일이 유실되지 않도록 처리 상태를 안전하게 관리한다.
- AI 응답이 비어 있거나 형식에 맞지 않을 경우 결과를 그대로 노출하지 않고 오류 처리한다.
- 동일 요청의 중복 처리로 불필요한 API 비용이 발생하지 않도록 요청 상태를 관리한다.

### NFR-04. 보안 및 개인정보

- API 키와 비밀 값은 환경 변수 또는 안전한 비밀 저장소로 관리한다.
- 업로드 파일은 허용된 경로와 확장자만 처리한다.
- 파일명과 문서 내용은 화면에 출력할 때 XSS 등 코드 실행이 발생하지 않도록 이스케이프한다.
- 문서 내용과 AI 결과를 로그에 원문 그대로 남기지 않도록 한다.
- 외부 AI API로 전송되는 데이터와 보관 정책을 사용자에게 안내한다.

### NFR-05. 유지보수성

- 파일 처리, 텍스트 추출, AI 분석, 결과 변환 로직을 분리한다.
- AI 모델이나 프롬프트를 변경해도 다른 기능에 미치는 영향을 최소화한다.
- 주요 오류와 처리 시간은 원문을 노출하지 않는 형태로 기록한다.

### NFR-06. 접근성

- 키보드만으로 파일 업로드와 결과 확인이 가능해야 한다.
- 버튼·입력 요소에는 의미가 분명한 이름을 제공한다.
- 색상만으로 상태를 구분하지 않고 텍스트 또는 아이콘을 함께 제공한다.

## 8. 데이터 요구사항

### 8.1 입력 데이터

- 파일명
- 파일 형식
- 파일 크기
- 파일 원문 또는 추출 텍스트
- 요약 길이 옵션
- 출력 언어 옵션

### 8.2 출력 데이터

- 처리 상태
- 문서 유형·주제
- 한 문단 요약
- 핵심 내용 목록
- 키워드 목록
- 결론·주장
- 중요 사실과 수치
- 후속 조치·질문
- 근거 위치 정보(가능한 경우)
- 오류 코드 및 사용자 안내 문구

## 9. AI Agent 동작 기준

- 역할: 업로드된 문서의 내용을 분석하고 사실 기반 요약을 생성하는 문서 분석 보조자
- 원칙: 원문 근거 우선, 불확실성 표시, 과도한 추론 금지, 출력 형식 준수
- 환각 방지: 원문에 없는 사실·출처·수치를 생성하지 않으며, 근거가 없으면 `확인 불가`로 표시한다.
- 결과 검증: 필수 항목 누락, 비정상적으로 짧은 응답, JSON 또는 구조화 형식 오류를 애플리케이션에서 검증한다.
- 안전 고지: 분석 결과는 참고용이며 전문 자문이나 최종 결정을 대체하지 않는다는 문구를 표시한다.

## 10. 주요 사용 사례

### UC-01. 보고서 요약

사용자가 보고서를 업로드하면 시스템은 보고서의 목적, 핵심 내용, 결론과 후속 조치를 요약하여 제공한다.

### UC-02. 회의록에서 할 일 찾기

사용자가 회의록을 업로드하면 시스템은 결정사항, 담당자, 일정, 미해결 질문을 구분하여 표시한다. 원문에 정보가 없으면 해당 항목을 비워 두거나 확인 불가로 표시한다.

### UC-03. 분석 실패 재시도

문서 추출 또는 AI 분석에 실패한 경우 시스템은 실패 원인을 안내하고 사용자가 같은 문서를 다시 시도하거나 다른 문서를 선택할 수 있게 한다.

## 11. MVP 수용 기준

- 지원 형식의 정상 문서를 업로드할 수 있다.
- 지원하지 않는 형식과 제한 용량 초과 파일이 적절한 안내와 함께 거부된다.
- 정상 문서에서 텍스트가 추출되고 분석 요청이 실행된다.
- 분석 결과에 요약, 핵심 내용, 키워드, 결론 또는 주요 주장, 후속 조치 항목이 표시된다.
- 원문에 없는 정보가 사실처럼 표시되지 않으며, 근거를 확인할 수 없는 항목은 확인 불가로 처리된다.
- 분석 중·완료·실패 상태가 사용자에게 구분되어 표시된다.
- 결과를 복사하거나 Markdown/TXT로 다운로드할 수 있다.
- AI API 오류와 처리 시간 초과 시 내부 정보가 노출되지 않는 사용자용 오류 메시지가 표시된다.
- API 키와 문서 원문이 소스 코드 또는 일반 로그에 노출되지 않는다.

## 12. 테스트 요구사항

### 정상 시나리오

- 짧은 한국어 TXT 업로드
- 여러 페이지의 텍스트 기반 PDF 업로드
- 요약 길이와 출력 언어 변경
- 결과 복사 및 다운로드

### 예외 시나리오

- 빈 파일
- 손상된 PDF
- 지원하지 않는 확장자
- 파일 용량 초과
- 이미지로만 구성된 PDF
- AI API 키 누락 또는 API 오류
- 네트워크 단절과 처리 시간 초과
- 원문에 결론·담당자·일정이 없는 문서

각 테스트는 입력, 기대 결과, 실제 결과, 통과 여부를 기록한다.

## 13. 운영 및 관리 요구사항

- AI API 사용량과 오류율을 확인할 수 있는 최소한의 운영 로그가 필요하다.
- 로그에는 파일 원문, API 키, 개인정보 등 민감정보를 포함하지 않는다.
- 모델명, 프롬프트 버전, 처리 시간은 결과 품질 개선을 위해 식별 가능한 메타데이터로 관리할 수 있다.
- 문서 보관 기간과 삭제 정책은 서비스 공개 전에 명시한다.

## 14. 향후 개선 방향

- DOCX, HWP, 이미지 및 OCR 지원
- 여러 문서의 비교·통합 요약
- 사용자 계정과 분석 이력 관리
- 문서 유형별 분석 템플릿
- 인용문과 페이지 기반 근거 강화
- 요약 품질 평가 및 사용자 피드백 반영
- 조직용 권한 관리와 감사 로그
